# 2026-04-21 Mini-SGLang Synthetic Gloo Probe

## Scope

Answer two practical questions on macOS without needing a runnable Linux + CUDA Mini-SGLang
server:

- can a `uv`-managed PyTorch wheel run CPU `torch.distributed` with Gloo here?
- if we model Mini-SGLang's CPU control-plane traffic using the external Gloo benchmark
  binaries, what is the retained delta between stock Gloo `uv` and the Myelon transport?

## Wheel-backed torch probe

Environment:

- `uv 0.9.26`
- Python `3.12.10`
- `torch 2.9.1`

Command:

```bash
uv venv .venv-gloo --python 3.12
source .venv-gloo/bin/activate
uv pip install 'torch<2.10.0'
python benchmark/synthetic/torch_gloo_smoke.py
```

Observed output summary:

- `torch.distributed.is_available() == True`
- `torch.distributed.is_gloo_available() == True`
- two-rank CPU `all_reduce` and `broadcast` both passed
- the wheel shipped:
  - `libtorch_cpu.dylib`
  - `libtorch_python.dylib`
- the wheel did **not** ship a standalone `libgloo` dylib

Net:

- using `uv` to create the venv works fine
- using that wheel to run CPU Gloo works fine
- pointing that wheel at an arbitrary external custom Gloo build is not a realistic runtime
  path on this host because there is no standalone `libgloo` to swap

## Synthetic Mini-SGLang control-plane comparison

Command:

```bash
python benchmark/synthetic/bench_gloo_control_plane.py \
  --benchmark-dir ../gloo/build-mpi-uv/gloo/mpi/benchmark
```

The proxy mappings are:

- scheduler broadcast:
  `SchedulerIOMixin._recv_msg_multi_rank0/_rank1`
- NCCL UID broadcast:
  `init_pynccl(... broadcast_object_list ...)`
- free-memory allreduce:
  `Engine._sync_get_memory`

### Retained p50 comparison

```text
+------------------------+-------------+----------------+---------------+
| Proxy                  | UV p50 us   | Myelon p50 us  | P50 speedup   |
+------------------------+-------------+----------------+---------------+
| scheduler broadcast 4B |       91.33 |          37.75 | 2.42x         |
| scheduler broadcast16B |       89.42 |          38.96 | 2.30x         |
| NCCL UID bcast   256 B |       81.08 |          46.21 | 1.75x         |
| NCCL UID bcast 1.00KiB |       95.08 |          33.79 | 2.81x         |
| free-mem allreduce16 B |      413.17 |         248.54 | 1.66x         |
| small allreduce 1.0KiB |      640.96 |         341.04 | 1.88x         |
+------------------------+-------------+----------------+---------------+
```

## Net

- If Mini-SGLang could use the custom Myelon-backed Gloo path for its CPU coordination
  traffic, the retained synthetic deltas on this host are meaningful rather than marginal.
- The likely gains are strongest for rank-wide broadcasts and still positive for tiny
  allreduces.
- The blocker is integration route, not whether the transport helps:
  the PyTorch wheel can run Gloo, but it cannot simply be redirected to an external custom
  Gloo library at runtime.
